# 核心方向优先的新闻雷达页面设计

状态：用户已于 2026-08-12 确认视觉方向，待书面规范复核后进入实施计划。

## 1. 目标

页面首要回答“今天最值得关注的是哪些板块或概念”。主题分数用于内部聚合和排序，不作为用户阅读重点；新闻数量和主题分数只以弱化的小字元数据展示。

本次仅调整网页的信息架构与视觉层级，不改变新闻采集、主题聚合、热度计算、新闻排序和事实核验规则。

## 2. 页面结构

页面自上而下固定为：

1. 报告标题、日期、时段与数据截止时间。
2. 单行核心方向导航。
3. 核心方向 01 的完整内容。
4. 核心方向 02 的完整内容。
5. 其余核心方向按排名依次完整展示。
6. 其他重要新闻。
7. 待核验线索，作为页尾紧凑附录并默认收起。

主题之间不插入第二套主题摘要或预告。每个主题直接承接下一个主题，形成连续的主阅读流。

## 3. 明确移除的内容

- 首屏或正文前部的全部单条新闻热榜索引。
- 主题强度仪表、进度条或柱状图。
- 新闻总数、待核验数、来源数等突出统计卡片。
- 大字号主题分数或把分数作为视觉主角的设计。
- “接下来的方向”摘要区及其中的主题卡片。
- 任何与顶部方向导航重复的第二套主题列表。

## 4. 顶部核心方向导航

- 仅显示按重要程度排序的主题名称，例如“AI算力 / 存储”“中东 / 油气”。
- 每个名称链接至对应主题锚点。
- 不显示主题分数、新闻数、图表或说明文案。
- 当前主题或第一主题使用品牌蓝强调，其余为中性灰。
- 桌面端保持一行；空间不足时允许水平滚动，不换成大块卡片。
- 导航由报告主题数据动态生成，不写死主题名称或数量。

## 5. 核心方向区块

每个主题区块依次包含：

1. 小号眉题“核心方向 NN”。
2. 主题完整名称。
3. 主题新闻数和聚合分数，例如“5条 · 420”，使用小号浅灰文字。
4. 一段紧凑的核心催化说明。
5. 该主题下按既有规则排序的完整新闻条目。

主题名称是区块的视觉中心。分数与新闻数不得使用大字号、强调色、进度条或独立统计卡片。主题之间使用留白和细分隔线区分，不使用风格突兀的深色大面板。

每个主题拥有唯一、稳定的 HTML 锚点。跨主题的新闻展开、折叠状态互不影响。

## 6. 新闻条目完整性

主题化展示不得牺牲原报告的信息完整性。每条新闻继续保留适用字段：

- 标题与核心信息。
- 可点击的具体原文来源及统一换算后的北京时间。
- 对应市场的盘前、盘中或盘后标注。
- 传播渠道、信号与热度变化。
- 可取得时的市场反馈及其观测时间。
- 判断边界、关联逻辑与个股映射。
- 原有核验链接和来源说明。

只有来源链接而没有额外详情的条目直接展示来源，不增加空的“展开详情”按钮。存在详情时，展开控件必须具有唯一标识，并支持键盘和正确的可访问状态。

## 7. 其他重要新闻

全部核心方向结束后展示“其他重要新闻”。该区域用于承载重要但不适合并入现有主题的消息：

- 保留完整新闻详情与核验链接。
- 沿用既有新闻排序规则。
- 不人为创建主题分数，也不恢复冗长的全量新闻索引。

## 8. 待核验线索

- 位于页面最末端，默认收起。
- 收起状态仅显示紧凑标题“待核验线索 · N”。
- 展开后逐条显示线索、缺口、来源和必要说明。
- 标题字号和视觉权重低于主题标题及新闻标题。
- 不参与主题分数、主题排名或新闻排名。
- 链接继续执行 HTTP(S) 安全过滤；控件支持键盘、焦点和展开状态。

## 9. 视觉语言

- 延续现有研究终端式浅色界面和窄版左侧报告归档。
- 主文字使用深蓝灰，品牌蓝只用于链接、当前方向和少量交互状态。
- 背景以白色和极浅灰为主，通过细边框与留白建立层级。
- 不采用深色终端面板、报纸版式或大面积装饰卡片。
- 信息层级依次为：报告标题、主题名称、新闻标题、核心催化、元数据、待核验附录。

## 10. 响应式行为

### 桌面端

- 左侧归档保持当前窄宽度。
- 核心方向导航保持单行并可横向滚动。
- 正文充分利用剩余宽度，但控制行长以保证阅读性。

### 移动端

- 沿用现有移动报告选择方式，隐藏桌面左侧栏。
- 核心方向导航横向滚动。
- 主题和新闻使用单列布局。
- 小号分数元数据不得挤压或截断主题名称。
- 待核验线索默认收起。
- 在 390 × 844 视口下不得产生页面级横向溢出。

## 11. 数据与兼容性

生成链路保持：Markdown → ReportDocument → 固定模板/渲染器 → dist HTML。

- Markdown 是报告内容的唯一事实来源，不手改结果 HTML。
- 主题化文档使用本设计；旧版非主题化 Markdown 继续兼容原有平铺列表和筛选逻辑。
- 主题化页面不再渲染旧版全量新闻索引和旧筛选区。
- 构建必须确定性输出；相同输入应生成相同 HTML。
- 模板、样式和脚本继续固化在代码中，每日仅变化 Markdown 与生成结果。

## 12. 验收标准

### 结构

- 页面没有正文前的长新闻索引。
- 页面没有“接下来的方向”区块、主题强度仪表、突出统计卡片或大号主题分数。
- 核心方向从 01 到 N 按聚合排序逐个完整展示。
- 每个方向下保留完整新闻详情，不只显示概述。
- “其他重要新闻”位于全部核心方向之后。
- “待核验线索”位于页面最后且默认收起。

### 交互与内容

- 顶部方向链接正确跳转至对应主题。
- 分数与新闻数仅以小号浅灰元数据展示。
- 新闻来源链接、时间、市场时段、市场反馈、判断边界和热度变化无回归。
- 新闻展开控件、主题锚点和待核验控件不存在重复 ID。
- 待核验项目不计分、不参与排名。

### 质量

- 桌面端与移动端均无横向溢出，信息层级一致。
- 键盘可操作展开控件，并正确维护可访问状态。
- 浏览器控制台无错误。
- 旧版非主题化报告通过回归测试。
- 根项目测试、网页测试和干净快照测试全部通过。
- 重新构建后的 dist 与模板输出一致，且公共发布检查通过。

## 13. 非目标

- 不修改主题聚合、热度评分、新闻评分或排序算法。
- 不重新分类本期新闻，也不改变报告事实内容。
- 不新增行情图表、主题仪表盘或交易建议。
- 本设计确认不等于授权合并、推送、部署或重新开启自动化任务。
