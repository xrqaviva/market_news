# 报告归档窄侧栏与日期树设计

## 背景与目标

当前桌面端报告归档将每份报告按“日期 + 时段”平铺，并占用220px固定宽度。目标是在不改变新闻内容和报告切换能力的前提下，提高正文屏幕利用率，并把归档改成清晰的“日期 → 时段”两级树。

## 已确认设计

- 采用静态两级树，不增加折叠操作。
- 日期为一级节点，按最新日期在上排列。
- 时段为二级链接，同一天固定按盘前、盘中、盘后排列。
- 历史元数据“收盘”只在导航展示层规范为“盘后”；报告正文和原始Markdown不改动。
- 当前报告只高亮二级时段链接；日期节点不作为链接。
- 桌面端侧栏和顶部品牌列由220px缩至168px。
- 移动端仍隐藏侧栏并使用现有报告下拉框；选项保持“日期 · 时段”语义。

## HTML结构与数据流

`web/build.py`继续以完整报告索引作为唯一输入。归档渲染器先按日期分组，再按日期降序、时段优先级排序，输出语义化列表：归档根列表包含日期组，每个日期组包含日期标签和时段链接列表。

每个二级链接继续保留原有相对HTML地址与当前页的`aria-current="page"`。JavaScript仍通过归档区域中的全部链接生成移动端下拉选项，因此不新增第二份导航数据，也不改变报告跳转方式。

## 视觉规则

- 168px侧栏以正文屏效优先，同时保留完整日期和四字以内时段标签的空间。
- 日期使用较弱颜色、小字号和等宽数字，承担分组标题而非操作项。
- 二级链接缩进，并使用左侧树枝线或等价的细线连接；当前项使用现有蓝色强调和深色背景。
- 组间距大于组内距，形成清楚层次；不使用大面积卡片或额外按钮。
- 820px及以下的现有移动端断点和正文布局保持不变。

## 兼容性与异常边界

- 时段排序优先使用报告`slot`：早间为盘前、日间为盘中、下午及收盘为盘后；未知时段排在已知时段之后，并保留原标签，避免丢失报告。
- 同一日期、同一时段若未来出现多份报告，全部保留，并以时间字段和稳定输入顺序确定顺序，不覆盖链接。
- 报告索引为空的构建错误仍由现有构建验证处理，本次不新增空状态页面。
- 新闻筛选、详情展开、来源链接、热点权重、首页重定向和公开安全规则均不在本次改动范围。

## 测试与验收

1. 单元/渲染契约：构造跨日期和同日多时段索引，断言日期只出现一次、日期降序、同日盘前在盘后之前、“收盘”导航显示为“盘后”，当前链接保留`aria-current`。
2. 集成构建：重建全部历史HTML，断言每份报告均有两级树且所有归档链接仍能解析。
3. 移动端兼容：下拉选项数量与报告数一致，选项包含日期和规范化时段，当前报告正确选中。
4. 桌面浏览器UAT：确认侧栏约168px、正文宽度增加、日期和时段层次清楚、2026-07-30同时显示盘前和盘后、报告切换正常。
5. 回归：新闻筛选、Top 10详情展开、后续条目直接来源、无横向滚动和控制台零错误。
6. 安全与发布：公开树安全扫描、JavaScript语法、生成资产一致性、`git diff --check`和完整测试套件通过后，才同步公开站点。

## 权限与发布边界

源码、测试、生成HTML和UAT记录在隔离分支内修改。公开仓库同步、提交和推送沿用用户已授权的站点发布流程；不修改定时任务、新闻Markdown或主工作区其他未提交内容。

## 非目标

- 不增加月份第三级。
- 不增加日期折叠、搜索或分页。
- 不重新设计移动端导航。
- 不改变任何新闻排序、评分或内容字段。
