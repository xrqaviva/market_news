# A股短线新闻雷达项目说明书设计

## 1. 目标

新增一份独立、长期维护的项目说明书，作为使用者和维护者共同使用的权威入口。读者无需通读历史会话、报告和设计文件，即可理解项目为什么存在、采集什么、如何计算热度、怎样运行、产物之间是什么关系、哪些能力已经完成，以及如何验收和排错。

说明书不仅介绍方法，还要持久化以下内容：

- 全部标准工作步骤；
- 已确认的产品与技术设计；
- 历史实施计划及完成状态；
- UAT与集成测试用例；
- 已执行测试的实际结果和证据路径；
- 已知限制、暂停事项、技术债和后续路线；
- 文档自身的维护和变更规则。

## 2. 目标读者

说明书同时服务两类读者：

1. **使用者：** 需要理解报告覆盖范围、时间口径、热点权重、核验链接、可靠性边界和阅读方法。
2. **维护者：** 需要运行采集、生成报告、维护热度基线、执行测试、处理失败、构建网页和判断哪些外部动作已获授权。

文档从业务解释逐步进入技术运行细节，避免普通读者一开始就被实现文件淹没，同时保证维护者能够追溯到具体证据和测试。

## 3. 产物与位置

最终说明书固定保存为：

```text

```

该文件是项目说明的唯一权威入口。历史设计、计划、证据、报告和测试代码继续保留在原路径，说明书通过相对链接引用它们，不复制全部原文，也不删除历史记录。

本次说明书编写过程保存在：

```text

```

## 4. 状态模型

所有能力、来源、计划和测试采用统一状态，禁止只写模糊的“支持”或“完成”：

| 状态 | 含义 |
|---|---|
| 已完成 | 文件或功能已经实现并存在于明确路径 |
| 已验证 | 已在记录的时间、环境和前置条件下实际运行成功 |
| 暂停 | 能力或任务有实现基础，但依据用户要求当前不运行 |
| 受限 | 受登录、付费墙、动态渲染、接口、站点策略或外部认证限制 |
| 规划中 | 已有设计或计划，但尚未完成实现或验收 |
| 历史口径 | 曾经使用、后来被新规则替代，仅为理解演进而保留 |

每项“已完成”或“已验证”尽量附代码、报告、证据、提交或测试结果路径；没有证据时不得升级状态。

## 6. 来源矩阵设计

来源不只列名称。每一类来源至少记录：

- 来源或平台；
- 在雷达中的角色：首发、官方确认、媒体扩散、社区传播、榜单发现或行情反馈；
- 主要入口和具体核验路径规则；
- 页面可见字段；
- 是否需要登录或会员；
- 当前状态和最近验证日期；
- 已知限制和失败降级方式；
- 典型证据文件。

来源按以下层次组织：

- 政府、监管、交易所、法定公告和公司IR；
- 国内财经媒体和公开电报；
- 海外通讯社、公司IR及科技/产业垂直媒体；
- 新闻与热榜聚合；
- 微博、雪球、X、淘股吧、韭研公社等社交和社区；
- 东方财富人气榜、同花顺/问财、开盘啦等市场传播与情绪渠道；
- 付费或尚未稳定接入的专业源。

说明书必须区分“作为事实来源”和“只作为传播热度证据”。财联社和东方财富属于媒体层，不得写成官方确认层；社区个股映射不得写成事实确认。

## 7. 热度与排序说明

说明书采用当前有效公式：

```text
热点权重 = 跨渠道覆盖25 + 热度变化30 + 绝对热度20 + 新鲜度15 + 持续频次10
```

需要明确：

- 分数只衡量传播，不衡量真假、投资价值或上涨概率；
- 可靠性、资金验证、个股映射、公告确认和深度判断不参与排序；
- 变化分是最高单项，因此热度激增和高热新出现可以改变主榜排序；
- 只有同一永久URL、同一命名字段、两个明确北京时间快照才能量化变化；
- 新URL按“新出现”处理，不从0计算百分比；
- 不同平台、不同帖子和不同字段的数值不相加；
- 旧新闻在本窗口显著升温时进入统一主榜，但新鲜度仍按原始时间计算；
- 页面没有显示数字时记录“未显示”，不能推断为0；
- 排名下降或互动减少可以由删帖、平台校准等造成，保留原值和边界。

说明书应给出至少一个严格双时点、一个新出现、一个旧闻异动和一个不可比较的示例，示例引用现有证据，不重新编造数据。

## 8. 时间与报告规则

说明书必须固定以下当前口径：

- 所有展示与窗口判断统一为`Asia/Shanghai`；
- 普通交易日从前一交易日00:00开始；
- 周一及节假日后首个交易日覆盖两个交易日之间的全部自然日；
- 页面只有日期时保留日期粒度，不补造00:00；
- 每条记录本轮最早可核时间，并将全部已取得节点按北京时间从早到晚排列；
- 不能证明全网首发时写“最早可核”，不能把本轮发现时间冒充发布时间；
- 具体文章、公告或帖子链接直接嵌入传播表，首页和搜索页不能替代单条核验路径。

报告结构说明覆盖Top 10深度与长尾紧凑条目。Top 10的关键信号、市场反馈、判断边界和后续变量不参与热点排序。标题只写新闻事实，不写激增、新出现、双时点或核验过程。

## 9. 工作流与产物关系

说明书展示以下标准数据流：

```text
交易日窗口与上一热度基线
        ↓
海外、国内、登录渠道三路采集
        ↓
事件去重、北京时间归一、传播链合并
        ↓
热度计分、Top 10冻结与深度补充
        ↓
报告Markdown + 证据表 + 热度基线 + 验收结果
        ↓
固定模板解析并生成HTML
        ↓
安全扫描、公开目录同步与静态发布
```

必须明确当前状态：Markdown报告和证据流程已多次运行；网页代码已在隔离分支`codex/news-radar-web`实现并测试，但尚未合入主分支；GitHub认证、首次推送和Pages发布处于暂停状态。不得将设计目标写成公网已上线事实。

## 10. UAT用例设计

UAT验证业务使用者能否正确得到和理解结果。每个用例采用固定字段：

| 字段 | 要求 |
|---|---|
| 编号 | 稳定编号`UAT-xxx` |
| 场景 | 用户要完成或判断的任务 |
| 前置条件 | 日期、登录、基线和来源条件 |
| 操作步骤 | 可复现步骤，不依赖会话记忆 |
| 预期结果 | 可观察且可判定 |
| 当前状态 | 已通过、未执行、受限或失败 |
| 实际结果 | 已执行时记录日期和结果 |
| 证据 | 报告、证据、测试或截图路径 |

至少覆盖：

- 普通交易日盘前窗口；
- 周一/节假日连续窗口；
- 北京时间换算及日期跨越；
- 具体帖子链接可核验；
- 严格双时点激增参与主榜；
- 无旧基线的新消息参与比较但不伪造增速；
- 旧闻重新升温；
- Top 10深度字段；
- 财报市场反馈；
- IPO询价、申购和上市日边界；
- 来源失败不等于零热度；
- 报告无“一眼结论”和操作建议；
- 不同报告网页切换；
- 15分钟超时后继续完成。

## 11. 集成测试设计

集成测试验证组件之间的数据契约。使用稳定编号`IT-xxx`，字段与UAT一致，另增加“涉及组件”。至少覆盖：

- 三路事件卡合并、去重和时间排序；
- 前一基线与当前快照的同URL同字段比较；
- 热点权重求和、降序和同分规则；
- 财报与IPO专项字段进入Markdown；
- Markdown报告结构契约；
- 多份Markdown解析为独立HTML；
- `reports.json`和最新报告入口；
- 固定模板语义结构；
- HTML不含本机绝对路径和私有文件名；
- 构建失败不覆盖上一版`dist`；
- 发布器默认dry-run和目标仓库校验；
- 页面桌面/移动端报告切换和详情展开；
- GitHub推送或Pages失败时保留本地Markdown与HTML。

未实际执行的用例必须写“未执行”，不能根据设计推断为通过。已有单元测试、结构验收和浏览器验收应链接到实际文件或提交。

## 12. 计划和完成情况持久化

实施计划总表至少包含：

- 设计或计划名称；
- 日期；
- 目标；
- 当前状态；
- 已完成内容；
- 未完成内容；
- 设计/计划文件；
- 实现、报告、测试或提交证据。

表格涵盖纯新闻热榜、V4扩容、交易日窗口、V5/V6报告、15分钟优化、财报与IPO修正、静态网页与GitHub Pages、自动任务和本次项目说明书。历史文件未被Git跟踪时也可以作为本地证据，但状态必须明确。

## 13. 安全和公开边界

说明书不能包含账号密码、Cookie、Token、Local Storage、浏览器历史、验证码、SSH密钥或其他凭据。平台登录状态只写是否验证成功和页面可见字段。

说明书本身位于内部工作仓库，不应自动复制到公开`market-news-site`。未来公开发布仍只允许`web/dist`白名单内容，且必须先执行敏感信息扫描。

## 14. 文档维护规则

- 文档顶部记录“最后核验日期”和适用版本。
- 新增来源或功能时，同时更新来源矩阵、状态总览、计划状态和相应测试用例。
- 热点权重、时间窗口或报告结构变化时，保留旧口径到设计决策记录，不静默覆盖历史。
- UAT和集成测试编号一经使用不得复用；废弃时标记“历史/废弃”并说明替代编号。
- 测试每次执行更新实际日期、结果和证据，不覆盖失败历史。
- 每次重大变更在变更记录新增一行，包含日期、变更、原因和证据路径。

## 16. 验收标准

- `docs/PROJECT_GUIDE.md`存在且可以单独理解项目；
- 覆盖本设计第5节列出的全部章节；
- 当前公式、时间窗口、链接要求、财报和IPO规则与最新设计一致；
- 来源矩阵包含角色、字段、登录、状态、限制和证据；
- 所有已完成/已验证状态均有路径或测试证据；
- UAT和集成测试均使用稳定编号和完整字段；
- 未执行、暂停、受限和规划中事项没有被写成通过或已上线；
- 所有内部相对链接指向存在文件，或明确标注目标仅存在于隔离工作树；
- 无`TODO`、`TBD`、空章节、凭据或不必要的本机绝对路径；
- 文档不包含交易建议或买卖信号；
- Markdown格式检查和链接目标检查通过；
- 本次任务的计划、发现和进度文件完整记录设计、实施、测试和结果。
