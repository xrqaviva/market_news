# 全窗口遍历式发现方法（2026-08-13 沉淀）

**生效日期：** 2026-08-13
**定位：** 每日报告发现阶段的操作方法权威记录。它回答一个问题：**在不依赖用户提示、不依赖关键词搜索的前提下，如何保证题材/信息不遗漏、全面、实时、准确。**

## 1. 为什么不能用搜索式发现

- 搜索只能找到“已经知道要问什么”的信息，天生漏掉“不知道存在”的条目。
- 2026-08-13 首版报告的全部漏项（腾讯资本开支、阿里云M890、马斯克10GW、Grok 4.6、宇树18000台、人形机器人出货97%、CME算力期货、TikTok解禁等）都发生在“被跳过的时间段”里，而非“搜索词不对”。
- 结论：**发现靠遍历，搜索只用于核验定位；遍历覆盖时间，搜索覆盖查询。**

## 3. 遍历发现层（每轮必做，并行或顺序皆可，但全部走到穷尽）

**A. 财联社电报流（主发现流）**
- 从截点起连续滚动加载，**每屏快照保留时间锚**，回走直至出现 P日00:00 之前的条目或加载控件消失。
- 每屏加载约30分钟历史；一天窗口约需40—60次滚动，实测约90秒可完成。
- 条目字段：`HH:MM:SS + 标题 + 财联社X月X日电 + /detail/<id> + 阅/评论/分享原值`。标题行与链接块分离，抽取时以时间行为条目边界、向后扫描取首个 `/detail/` 与 `阅` 值（注意条目内关联文章链接会先于自身评论链接出现，需以“评论(n)”行的链接为准）。
- 窗口边界：条目日期归属用正文“X月X日电/讯”判定；无日期标记的条目单独标注，不猜测。

**B. 当日早报/午报/收评（锚点对账流）**
- 早报（约07:00）、午报、收评各一篇，逐段把每个独立事实转成候选卡。
- 汇总稿只作发现与对账，不直接充当单条核验链接；核验必须落到该事实自己的详情页（可从A流或题材页取得）。

**C. 题材页文章流（主题补全流）**
- 对上一轮遗留题材与当日明显活跃题材（AI算力、人形机器人、半导体、医药、宏观等）逐一打开题材页并滚动至窗口起点。
- 作用：补齐A流之外的长文与专题稿，并为主题归属提供语义依据。

**D. 官方/公告/交易所 + 海外收盘（事实与宏观层）**
- 央行/发改委/部委官网、上交所/深交所公告入口、公司IR；海外用美股收盘、环球市场与主要指数稿。
- 官网列表页只作发现；单条必须落到公告/文章永久链接。

**E. 新浪7×24 API 回放（核验与补漏层，2026-08-14 增补）**
- 接口见《可用接口清单》第1节；page 递增回放到窗口起点（约23页/2300条，耗时约30秒）。
- 用途：①给财联社未收录/未核验的条目补**精确时间戳**（决定第一层/第二层归属）；②每个有 docurl 的条目直接作为**第二来源永久链接**（双源规则）；③回放中发现的遗漏条目进入候选账本。
- 注意：`ext.docurl` 是 JSON 字符串需二次解析；约6%条目无 docurl；正文日期归属以 `create_time` 为准。

## 4. 遍历操作规则（机械执行）

1. 从截点回走，**不到窗口起点不得停止**；加载控件消失才算穷尽。
2. 每次加载后记录：已加载条目数、当前最早时间、耗时；停滞（连续3次无新增）时记录并改用下一层继续。
3. 条目一律先入库（候选账本），**不得边看边筛**；排序、主题、排除是采集完成后的事。
4. 每条候选在交付前必须有最终状态：`ranked`、`merged_into:<event_id>`、`excluded:<原因>`、`pending_verification`；无状态即召回失败。
5. 截点纪律：截点之后（含采集过程中新增）的条目不入榜，标记时间并披露。

## 5. 交付前对账闸门

1. **早报/收评对账**：当日早报/午报/收评中的每个独立事实，必须在候选账本中找到处置状态；缺一条即失败。
2. **用户提示对账**：用户指出的任何条目若不在账本，先回到A—D层补遍历，不得用搜索替代。
3. **窗口覆盖对账**：A流的小时分布必须连续覆盖 [P日00:00, 截点]；缺口小时需说明来源失败原因。
4. **跨源对账**：财联社未收录的条目（如海外产业媒体独发）在报告"待核验线索"中保留事实与缺口，不因单一源缺失而静默丢弃。

## 6. 准确性规则

- 每条事实落到唯一详情页，以详情页正文为准；标题摘要不跨条目拼接（教训：一鸣食品与传智教育）。
- 时间、数字、主体、动作、对象任一不同即为不同事件，不得因同题材合并。
- 阅读/评论/分享原值保留原始数字，采集时点随值记录；不推算增速、不伪造分钟。

## 9. 每日启动协议（步骤0）

1. **登录态检查（先于一切采集）**：打开微博、雪球、X、淘股吧四个站点，用页面可见标记核验登录态（微博=用户链接/消息角标；雪球=登录后导航；X=Home时间线；淘股吧=个人中心可访问）。只读页面可见状态，不碰凭据。
2. **登录态缺失时**：自动打开对应登录页交用户自行登录（30秒内完成），登录后复验。
3. **登录态跨进程持久性**：浏览器配置是否跨 ZCode 进程保留尚未实测；每次新进程启动都必须执行本协议，不沿用旧结论。
4. 记录核验结果到 evidence，通过后进入第3节遍历发现层。

## 10. 盘前报告排序规则（2026-08-14 用户裁定，含修订）

**旧闻后置原则：** 上一交易日已影响过盘面的事件，对今日开盘的边际影响力弱，一律后置。

1. **旧闻界线（用户裁定修订）：** "昨日已定价"指事件在**上一交易日 UTC+8 12:00 之前**已发布/已发生——昨天中午之前出现的消息，昨天下午盘面与收盘已消化。**昨天 12:00 之后**发布的盘后公告、晚间新闻与今晨信息（如中芯/华虹 16:40 盘后财报、海光 18:44、中国移动 18:57、京东 18:03、昨夜美股时段、今晨央行操作）市场尚未定价，视为**今日新事件（第一层）**。界线是"昨天中午"，不是"昨晚 24 点"。
2. **第一层（前置）**：上一交易日 12:00 之后首次发布/发生的事件（含昨夜美股时段与今晨新信息），对今日A股开盘存在边际增量。
3. **第二层（后置）**：上一交易日 12:00 之前已发布/已发生且盘面已定价的事件（含全部 08-12 旧闻异动）。索引标注"昨日已定价"，卡片保留原始时间与再传播节点。
4. **已定价折扣（量化实现）：** 第二层条目在今日报告中按 **0.4 系数**折算热点分（`round(score × 0.4)`），五项明细同比例折算并在"变化"项吸收取整差，保证明细之和等于折算总分。
5. 两层内部均按热点权重分降序；跨层不比较分数。
6. 题材总分随折扣后的分数重算，题材按总分降序排列，题材内新闻按全局排名升序展示。
7. 报告头部必须提供"本窗口新增"清单，列出第一层全部条目与排名。

## 11. 防漏机制（2026-08-14 增补：涨停复盘与题材前瞻台账）

**触发背景：** 08-14 盘前版对照韭研公社盘前资讯审查，发现漏掉两个题材级板块（电力/算电协同、消费/影视）与一批公告/异动。根因：①管线没有涨停复盘数据源（连板高度、板块涨停数不可得）；②央视财经/新闻联播内容在财联社电报流覆盖率低；③公告类被热度分筛掉；④题材前瞻类（维生素、氢能、钠电池等）没有独立台账兜底。以下为固化规则：

1. **涨停复盘台账（每轮必建）**：收盘后从韭研公社/新浪涨停分析快讯/东财涨停池取得：连板梯队、板块涨停数、涨停事件映射（涨停→驱动事件）。台账是盘面事实附录，**不参与热榜计分**，与索引并列交付。
2. **驱动事件反查**：台账中每个涨停事件背后的驱动事件（政策、公告、财报、行业数据）逐一反查候选账本；未入榜的按正常流程补录（时间戳核验→分层→评分），无法核验的进待核验线索，**禁止静默丢弃**。
3. **题材前瞻台账（防低传播分丢失）**：行业动态类（维生素、氢能、钠电池、钙钛矿、商业航天、储能电芯等）即使单条传播分低，也必须在台账登记事实+来源+状态；重要题材（板块级、有涨停联动、有政策文件）按正常流程入榜，次要的登记台账。
4. **公告速览台账**：盘后公告全量登记（时间、公司、要点、状态：已入榜第N条/待核），确保公告类"不遗漏"与热榜质量分离。
5. **对账闸门升级**：第5节闸门增加一条——韭研公社（或任何外部盘前资讯源）中**每个板块涨停数与每个独立事实**，必须在候选账本/台账中找到处置状态。
6. **新增来源层**：央视财经（央视网财经频道 cctv.com/cj）、新闻联播摘要、东财/同花顺人气热榜、涨停池页——接入《可用接口清单》后按接口状态使用；未接入前以韭研公社+新浪快讯双源代替。

**2026-08-14 实证：** 对照韭研公社盘前版补录 29 条（第一层 27 条 + 第二层 1 条），报告从 51 条扩至 80 条；新增电力/算电协同、消费/影视两个题材；涨停复盘、公告速览两个台账章节；新增待核线索 13 条（韭研公社单源，如药明裁决、BD 1063亿、氢能报告、中科海钠、储能电芯、维生素、智能胰岛、NeMo Switchyard、上海软件规划、兆日科技、移远通信）。新浪7×24 API 回放为本次补录提供了精确时间戳与第二来源链接（新增来源节点 35 个，sources 487→522）。
