# 新闻雷达题材聚合方法、反漏采控制与验收台账

**生效日期：** 2026-08-11
**状态：** 当前方法与验收权威记录；本地生成页已完成真实浏览器 UAT，实现仍为本地提交，未推送、未部署、未发布。现有记录中的自动任务状态仍为暂停，但本轮缺少 Codex app 自动化只读接口，未独立读取其运行时状态。
**适用范围：** 题材优先 Markdown 报告、解析/渲染行为、人工 UAT 与后续每日工作流。

本记录以已获用户确认的题材聚合设计和 2026-08-11 报告实现为准。历史纯新闻热榜设计、旧报告和旧交接仅作历史证据；如有冲突，以本记录及已确认题材设计为准。本文是可读方法和 UAT 台账，不以对人类说明文字的固定短语匹配充当测试；题材公式、Markdown 语法和报告字段由解析、构建和报告行为测试锁定。

## 1. 题材方法与计分边界

1. 每轮从合格的单条主榜新闻动态生成题材；用户给出的题材名称只是示例，不能固定成每日清单。
2. 先识别细粒度标签，再用同义词词典归一展示名称。例如“AI算力 / AIDC / 数据中心”可归为同一上位题材，“人形机器人 / 具身智能”可归为同一上位题材。归一不改变事件事实、标题、来源或单条分数。
3. 题材必须同时满足：至少两条**不同事件 ID**的合格主榜新闻；产业链、事件链或共同催化具有可解释的语义关系；题材名称能覆盖全部成员。不得以“科技”“政策”“市场”等空泛词，或把机制、国家和事实无关的宏观消息凑成一组。
4. 单条热点分只衡量传播。题材分为全额累加：`theme_score = Σ associated_news.hot_score`。一条新闻属于多个题材时，向每个题材各贡献完整单条分，不拆分、不折扣。
5. 题材按题材分降序、成员数量降序、题材内最高单条分降序、规范化题材名称升序稳定排序；题材内新闻按原单条热榜排名升序。
6. 跨题材全额贡献只服务于各题材内部排序：不同题材总分不得再次相加并解释为市场去重总热度。页面和 Markdown 必须对跨题材副本显示关联题材及“跨题材重复计分”。
7. 每个题材中的每条新闻均保留完整卡片：原排名、事件 ID、标题、热点分、核心信息、具体来源直链和北京时间、关键信号/预期差、带时间市场反馈、判断边界、热度变化、发布时段与关联题材。未成题材的合格新闻进入“其他重要新闻”，字段完全相同，不因位置靠后而缩写。
8. 个股映射分为两层：直接映射必须由新闻主体、公告/监管/公司 IR 或可核产业资料直接支持；板块代表只说明产业链位置，必须写明“本轮新闻未确认新增订单或直接受益”。两层均不计分、不继承新闻或题材分数、不构成投资建议。
9. 待核验线索只展示已知事实、具体链接和待核原因；不进入单条主榜、不形成题材、不参与题材分或市场总分。

## 2. 时间、旧闻与市场反馈

- 所有可换算来源保留原始时区并转换为北京时间；只有日期或无可靠时区时，明确“分钟/时区未取得”，不得补造。
- 发布时段按新闻所对应市场标注，而非把报告运行时段误当作新闻时段：A 股使用中国市场盘前/盘中/盘后；美股使用美国市场盘前/盘中/盘后。一个报告可以同时含两类标签。
- 窗口外旧闻只有在本窗口有可定位的再次传播或同一永久 URL、同一字段、两个明确北京时间快照的热度异动时才可参与主榜或题材。原始时间、重现/升温时间和比较口径都必须保留；无可比基线只能写“新出现”或“不可比”，不能伪造增速。
- 对可观察的发布后市场反应，记录北京时间、对应市场时段、价格方向/幅度及来源；无法观测时写“不可得”并说明原因。市场反应是即时定价信息，不是新闻因果证明、长期认可或投资建议，也不参与任何新闻/题材分。

## 3. 反漏采工作流（2026-08-11 九条漏项的六类控制）

1. **来源广度清单。** 每轮保存官方/公司、国内财经媒体、财经社区与热榜、产业垂直媒体、海外主流及科技媒体的窗口清单、开始/停止时间和失败原因。不得以固定条数、Top 10 深挖或单源成功提前停止发现。
2. **财经与政策子流。** 国内流拆分公司公告/财报与资本运作、监管/央行/部委政策、行业规划与地方会议；早报、汇总稿仅作发现，内部每一独立事实必须生成候选卡。
3. **海外宏观子流。** 海外流独立覆盖利率/债券、地缘与能源、主要指数和企业财报，保留原始时区、北京时间、相关市场时段及可观察反应，避免把海外宏观排除在 A 股相关性审查之前。
4. **半导体融资与基础设施子流。** 对芯片公司融资、AI 算力融资平台、数据中心/电力基础设施投资、AIDC 交付与资本开支使用扩展关键词和来源清单；融资平台、具体项目投资和同题材公司事项先分别建事件卡，不因主题相似合并。
5. **同义词扩展。** 候选检索同时执行题材同义词、公司别称/产品名、中文/英文写法与上下游术语扩展；归一只用于题材命名，不能把不同主体、动作、对象或发生时间的事实压成一项。
6. **最终完整性对账。** 交付前把每个来源条目与候选账本对账。最终状态只能为 `ranked`、`merged_into:<event_id>`、`excluded:<明确原因>` 或 `pending_verification`；合并保留目标事件 ID，排除保留具体理由。对同一事实的核心媒体覆盖生成独立候选并进行跨媒体覆盖对账。任何无处置状态的条目都视为召回失败，超过常规时长也必须继续完成而非静默删除。

事件身份以**主体 + 动作 + 对象 + 发生时间**和具体 URL 判断；主题相同不等于同一事件。候选不确定时保留并标注边界，不以标题相似强行去重。

## 4. 精确 Markdown 语法

本节分开说明两个层次。**报告发布必填契约**要求使用下列完整结构：完整新闻字段、题材映射/风险边界、发布时段和待核字段都不得静默省略，且应按所列顺序呈现，随后由报告行为测试、独立审阅和真实 UAT 把关。竖线可使用全角 `｜` 或半角 `|`；方括号中的占位符是数据，不是字面文本。

**当前 parser 最低可解析语法**仅在存在 `## 单条新闻热榜索引` 时进入题材路径。它要求非空索引行、至少一个题材标题和题材 ID、非空核心催化、每个嵌套新闻标题及至少一个安全的具体来源链接、`其他重要新闻`章节，并结构性校验索引/成员/分数/副本关系。它并不单独强制所有发布字段，例如 `热点权重`明细、`发布时段`、直接映射、板块代表或题材风险边界。因此“可被 parser 读取”绝不等于“可发布”。以下是**发布层完整结构**，也是 parser 能从中读取题材数据的推荐规范：

```text
## 单条新闻热榜索引

| 原排名 | 事件ID | 新闻标题 | 热点分 | 关联题材 | 跳转锚点 |
|---:|---|---|---:|---|---|
| <rank> | <event_id> | <title> | <score> | <theme_id list or -> | [查看](#<event_id>) |

## 题材主线

### 主线<N>：<theme_name>｜<total_score>分｜关联新闻<count>条

**题材ID：** <theme_id>
**核心催化：** <nonempty catalyst>
**直接映射：**
- <name>（<six_digit_ticker>）：<direct evidence>
**板块代表：**
- <name>（<six_digit_ticker>）：<representative evidence; no direct-benefit claim>
**题材风险边界：** <boundary>

#### 新闻：<rank>｜<event_id>｜<title>｜<score>/100

**热点权重：<score>/100**（<breakdown>）
**核心信息：** <core>
| 传播渠道 | 北京时间 | 时段与信息 |
|---|---:|---|
| <channel> | <Beijing time> | [<exact source label>](https://...) |
**关键信号/预期差：** <signal>
**带时间市场反馈：** <feedback or unavailable reason>
**判断边界：** <boundary>
**热度变化：** <change / new / incomparable>
**发布时段：** <relevant-market session>
**关联题材：** <theme_id list; cross-theme disclosure when applicable>

## 其他重要新闻

#### 新闻：<rank>｜<event_id>｜<title>｜<score>/100
...（使用与题材内新闻相同的完整字段）...

## 待核验线索

### <pending title>
**已知事实：** <known facts>
**待核原因：** <reason>
[<exact source label>](https://...)
```

**当前 parser 结构校验：** 索引事件 ID 和排名唯一且排名升序；题材 ID 唯一；每题材成员数与标题声明相同且不少于两条；题材声明分等于成员分数之和；成员与索引/题材关联一致；同一事件副本的已解析字段一致；所有索引新闻恰好位于至少一个题材或“其他重要新闻”，且两者不得重叠；每个嵌套新闻块至少有一条安全的具体来源链接。

**发布层额外必填：** 除上述结构校验外，发布前还必须人工/行为验收完整的热点权重与核心信息、具体来源直链和北京时间、关键信号/预期差、带时间市场反馈或不可得原因、判断边界、热度变化、相关市场发布时段、关联题材披露，以及适用时的直接映射/板块代表/题材风险边界和待核已知事实/原因/链接。发布层字段缺失、顺序漂移或语义不合格时，不得以 parser 能通过为由发布。

## 5. UAT 与集成用例
