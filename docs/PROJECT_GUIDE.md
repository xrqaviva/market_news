## 1. 项目定位与阅读方法

本项目是面向A股短线信息发现的新闻雷达：在一个可复核的交易日窗口内，归并同一新闻事件的首发、转载、社区传播和可见热度，并按“正在被传播的程度”生成统一新闻主榜。它服务于信息发现、事实边界和传播轨迹记录，不提供买卖建议、仓位建议或“一眼结论”。

不把热度当作真实性，不把媒体/聚合稿当作官方确认，也不把个股行情反应当作新闻因果。公告、监管和公司IR可用于核实事实；社交和社区数据可用于衡量传播；两类信息分别记录。

建议按本章了解边界，再读第2章的状态标签、第3—6章的采集和事件方法、第7—8章的评分与入榜规则，最后以第9章核对报告应有字段。受Git管理的设计依据为[15分钟完整交付优化设计](superpowers/specs/2026-07-30-15min-full-delivery-optimization-design.md)。`superpowers/specs/2026-07-29-trading-window-compact-news-ranking-design.md`在当前分支未跟踪，故只记录路径，不生成在干净克隆中失效的链接。历史运行样本位于`../evidence/2026-08-03-0800-heat-agent.md`、`../evidence/2026-08-03-0800-heat-baseline.json`和`../reports/2026-07-31-0800-premarket-news-ranking.md`，均为主工作树历史产物，未复制到本分支。

当前有效方法以2026-08-03热度证据和最新设计为准；早期`HANDOFF.md`只作历史交接，不覆盖本说明书。状态标签的含义如下：

| 标签 | 含义与写法 |

## 3. 架构与数据流

采集分三路并行，全部先输出结构化事件卡而非先写叙事：

1. 海外宏观、财报、地缘和跨资产来源，负责原始时间、事实和跨时区信息。
2. 国内政策、产业、公告和公司来源，负责法定披露、媒体稿和A股相关事实。
3. 微博、雪球、X、NewsNow等动态渠道，负责具体永久链接、原始互动值、榜位及双时点变化。

每张卡至少带事件ID、事实性标题、最早可核时间、传播节点、具体链接、来源类型、热度原值、可比基线/变化结论、事实边界和缺失字段。处理顺序为：`上一窗口基线 + 三路事件卡 → 时间归一与事件去重 → 热度计分 → 临时Top 10深挖和长尾紧凑条目 → 交叉复核 → 同一结构化版本生成报告、证据表、热度基线和进度记录`。来源超时也必须产出来源、起止时间和失败类型，不能静默等待。

## 4. 新闻时间窗口与北京时间

所有候选纳入、传播链排序、快照比较和报告展示使用`Asia/Shanghai`。海外页面有明确当地时间和时区时，先按事件当日有效时区（含夏令时）换算；原始时间、原始时区和换算结果留在证据层。来源没有明确时区，标为“来源时区未确认”，不擅自换算。只有日期没有分钟时保留该日期并写“精确分钟未取得”，绝不补成00:00。

令`T`为当前A股交易日、`P`为交易所日历中的前一交易日、`C`为报告截点，主窗口为`[P 00:00:00, C]`。普通交易日从前一交易日00:00开始，覆盖前一交易日盘前、盘中、盘后及当前日截点前新闻；周一从上周最后一个交易日00:00开始；节假日后首日从节前最后一个交易日00:00开始，连续覆盖全部自然日的休市期间。临时休市以交易所日历为准，不用工作日或简单减一天推算。

窗口外旧新闻若在窗口内有可核重新传播，或满足量化变化条件，可标为“旧闻异动”并进入同一主榜。量化“明显升温”或“激增”只接受同一永久URL、同一字段、两个明确北京时间快照的绝对变化；榜位至少上升10位或由未上榜进入前20同样必须有同一永久URL、同一榜位字段和两个明确北京时间快照。跨平台同步只能作为覆盖、频次或重新出现证据，不量化增速；单快照旧闻只能标“重新出现、趋势数据不足”，不能写为升温或激增。条目同时展示原始发布时间、窗口内升温或重新出现时间、触发证据和当前传播路径，不能把旧闻重写成新首发。

## 6. 事件发现、去重与传播链

事件ID以“同一可陈述事实”为粒度稳定生成，例如`日期-主体-动作-对象`的规范化键；标题相似并不自动合并，数值、主体、时间或事实触发点不同则为不同事件。一个事件可有多个节点：首发/事实触发点、媒体转载、社区解释、热榜或互动快照。节点保留原链接和时间，不因归并而丢失传播链。

事件身份强制按**主体 + 动作 + 对象 + 发生时间**判断，不能只按行业或主题词聚类。伊朗提出赔偿条件与特朗普反向要求伊朗赔偿、机器人产业规划与机器人会议、同一公司的融资平台与具体项目投资，均须先建立独立事件卡，再判断是否仅在展示层归入同一事件簇。主题相同不等于事件相同。

事实触发点是公告发布、官方披露、公司财报、明确报道或可定位原帖所述的可核事实；传播节点是对该事实的转载、讨论、榜位或互动变化。两者可以同一URL，但不能互相替代：传播广不提高事实真实性，官方事实也不自动具有社交热度。相同话题的不同永久URL是不同热度节点；只有确认指向同一事实时才归入同一事件，且各平台数字分别保留。

去重时优先比较具体URL、主体、动作、对象、最早时间和数字，再决定是否合并。早报汇总只用于发现，其内每一个独立事实单独成事件；同一公司两份不同公告、同一主题的新政策和旧政策重传也不能因关键词相同而合并。无法确定是否同事件时保留为候选并标注边界，不能为了压缩条目臆断。

所有来源条目实行**零静默丢弃**：进入候选账本后，最终状态只能是`ranked`、`merged_into:<event_id>`、`excluded:<明确原因>`或`pending_verification`。合并必须保留目标事件ID，排除必须保留分数与具体理由；任何没有状态的来源条目都视为召回验收失败。若同一事实在财联社、东方财富等至少两家核心媒体出现，必须生成独立候选卡，并在交付前完成跨媒体覆盖对账；媒体共识不直接提高真实性，但不得被无声忽略。

## 7. 热度体系

热点权重满分100，只衡量传播，不衡量真假。资金验证、公告确认、可靠性、个股映射、市场反馈和深度判断均不参与排序。当前公式为：**覆盖25 + 变化30 + 绝对热度20 + 新鲜度15 + 频次10**。覆盖计独立平台和传播链；变化只使用严格可比的绝对增量；绝对热度使用平台内原始互动/榜位的规范化位置；新鲜度衡量窗口内首次出现或时间接近截点；频次衡量已核节点持续出现。五项相加为主榜分数。

严格可比的前提是同一永久URL、同一字段、同一平台、双时点。只计算绝对变化，不制造百分比；网页只显示标签不显示数字时，不能推断为0。新URL或无同口径旧基线一律标“新出现”，可参与变化项和排序，但不能称为“激增”。不同平台的数字不得相加，也不把微博话题阅读与某条微博的转评赞、或雪球收藏与未明确可比的互动拼成增量。

示例：同一条淘股吧永久帖从373浏览/19评论变为6814/412，可分别记浏览`+6441`、评论`+393`；这是可比变化。一个新微博话题页与一条新微博帖即使主题相同，也只能分别记“新出现”，不跨URL计算增长。X的浏览量和微博的点赞都可作为各自平台内热度证据，但不能相加成“全网热度”。当前可用证据中**尚无合格的旧闻异动样本**：没有同时具备原始时间、窗口内再升温时间、同URL同字段双时点与可复现证据路径的样本，因此不伪造数值；未来取得合格样本后必须四项并列。

## 8. 主榜准入与排序

主榜收录窗口内与A股短线信息发现有关、具有可核事实或可定位传播节点的合格新闻；旧闻异动也在同一榜中。资金验证和公告确认也不是入榜前提：它们与可靠性标签、市场反馈、板块/个股映射和待确认项一样随条目披露，但不参与热点权重；不单列“未经确认观察池”，也不因缺少资金验证、公告确认或行情反馈而删除已合格新闻。

按五项合计分数严格降序排列，分数相同则依次比较变化分、覆盖分、新鲜度分，再比较事件最早可核时间（较早者在前）；仍完全相同则以稳定事件ID升序，确保重复生成不随机换序。主榜不固定10条：所有达到准入条件的新闻均展示，Top 10仅代表需要深挖的前十条。

标题只做事实性概括，不能写“升温”“激增”“双时点”“趋势未知”等监控结论。来源存在冲突时保留不同口径与时间，采用现有证据支持的最弱结论；未能解决的实质冲突降低表述强度、移出Top 10深度结论或暂不入榜。

## 9. 报告结构与专项规则

每个主榜条目至少有事实性标题与核心信息、总分及五项构成、最早可核时间和传播链（均按北京时间从早到晚）、具体核验链接、原始热度/基线与变化结论、可靠性或事实边界、尚未确认项，以及可选A股附注。链接嵌入“消息或热度”的详情文字；首页和搜索页不能替代具体文章、公告或帖子。

Top 10追加深度字段：预期差或新增事实、带时间的市场反馈、因果/真实性边界和后续待核变量。深度字段不参与热度评分。第11名以后使用紧凑条目，但不遗漏核心信息、时间、渠道和具体链接；“紧凑”不等于只保留标题或只给平台首页。

窗口内新发财报必须写盘后交易反馈，若无盘后交易则写财报后的首个可交易时段，并附北京时间和“即时市场定价”方向；价格反馈不等于长期认可，且不同来源的同期快照可并列而不伪造连续行情。正式发行阶段IPO条目必须含询价日、申购日和证券代码，申购日与上市日不得混写；未披露上市日就写未披露。报告不输出操作建议或买卖信号。

**事件日期字段（2026-08-17 机制化）：** 当新闻明确提到未来日历事件（IPO 发行/聆讯、限售解禁日、停牌起始日、会议/决议日、数据发布日等）时，详情卡必须输出 `**事件日期：** YYYY-MM-DD（依据：来源与原文）`，日期必须可机器解析；未披露写 `未取得（原因）`，绝不补造。该字段供下游事件日历机械并入，是「公司级事件不漏入事件日历」的结构化入口。

## 10. 标准运行步骤

以下步骤从一次任务实际触发时开始计时。维护者只在交易日闸门允许且输入可核时运行；本章描述的是当前设计的操作契约，不把尚未合入的网页或暂停的发布动作当作本分支已经可执行的流程。

1. **确认交易日与截点。** 查询交易所日历，确认当前交易日`T`、前一交易日`P`和报告截点`C`；按第4章建立`[P 00:00:00, C]`窗口。周一、节假日后首日和临时休市均以交易所日历为准。记录触发时间、操作者/任务ID和本轮时段；若闸门不允许，记录“未运行”及原因，不用自然日替代交易日。
2. **载入输入基线。** 读取上一窗口的事件、关键词和同一永久URL/同一字段的热度基线。基线仅用于比较与减少重复采集，不能代替本轮快照；不存在同口径基线时把当前节点标为“新出现”。
3. **三路采集并登记失败。** 并行收集`海外宏观与财报`、`国内政策与公告`和`登录渠道热度`三组结构化事件卡。每组既要返回已核事件，也要返回来源、开始/停止时间和失败类型；财联社、东方财富及当日海外核心来源须保存窗口清单，不得以固定条数提前结束，也不得以未返回结果静默等待。
4. **归一、去重并形成临时候选。** 将时间换算为北京时间，保留原始时区；按主体、动作、对象、发生时间和具体URL判定事件身份，保留全部传播节点。按第7—8章计分，在第4分钟形成临时Top 10和长尾候选；此时Top 10只决定深度，不得冻结来源发现。重大突发可以替换Top 10末位，但原候选仍保留处置状态。
5. **补齐Top 10并交叉复核。** 海外、国内和热度工作分别补充Top 10深度字段、永久链接和同字段双时点；随后互相检查时间、数字、事实边界、标题和链接。未解决冲突采用最弱表述、移出深度结论或暂不入榜。
6. **从单一结构化版本生成。** 一次生成报告Markdown、证据表、热度基线、验收结果和进度记录。不得分别手改这些产物而形成版本分叉；发现错误时回到事件卡修正后重新生成。
7. **验收。** 检查窗口与北京时间、具体链接、分数求和及排序、Top 10字段、长尾字段、失败记录和产物一致性；逐项执行来源窗口清单、跨媒体覆盖对账和候选处置状态检查。任一来源条目没有`ranked`、`merged_into`、`excluded`或`pending_verification`状态，均不得宣告完成。异常和缺失应写入验收/进度记录，不能用推测填补。
8. **交付。** 记录端到端耗时、阶段里程碑、来源失败、SLA状态和交付物路径，交付已通过验收的完整结果。网页构建、公开同步、提交、推送及发布仅在其前置条件、分支状态和授权均满足时另行执行；当前这些外部动作见第13与第17章的暂停状态。

## 11. 15分钟并行流程

15分钟是正常网络、主要来源可用且必要登录会话有效时的端到端服务目标；计时从任务触发开始，到报告、证据、基线、验收和进度记录全部落盘且可交付为止。它不是删减来源、缩短窗口或交付半成品的理由。

性能优化只冻结Top 10深挖名单，不冻结来源发现、长尾事件化或召回对账。固定候选数量、固定每组返回条数、提前停止财联社/东方财富窗口遍历，均不属于允许的提效方式；覆盖对账超过15分钟时继续完成。

| 时间预算 | 主任务 | 三路并行工作 | 阶段完成标准 |
|---|---|---|---|
| 0—4分钟 | 启动真实计时、载入基线、接收事件卡 | 海外宏观与财报；国内政策与公告；登录渠道热度 | 候选卡和来源失败记录齐备。 |
| 4—6分钟 | 时间归一、去重、计分、冻结候选 | 继续补缺；重大突发按记录替换候选 | 临时Top 10与长尾形成。 |
| 4—9分钟 | 分配深挖缺口 | 三组复用为海外/国内深挖与热度链接、双时点补齐 | Top 10深度字段达到可复核状态。 |
| 8—11分钟 | 汇总问题并修正事件卡 | 对方事件的事实、数字、链接、标题和热度口径交叉复核 | 冲突解决或已降级披露。 |
| 11—13分钟 | 从统一数据生成全部产物 | 已完成组协助补缺或复核 | 报告、证据、基线、验收、进度记录落盘。 |
| 13—14分钟 | 自动/人工验收 | 按需修正来源记录和字段 | 时间、链接、分数、排序和字段通过。 |
| 14—15分钟 | 最终一致性核对与交付 | 不以提前结束减少既定覆盖 | 交付物一致且可交付。 |

若单一来源或某个并行工作超过其阶段预算，停止无期限等待，保留已经返回的事件卡与失败记录，并由先完成的工作补齐可补部分。第15分钟是SLA检查点：**超过15分钟仍继续完成**，必须记录实际耗时、超时阶段和原因，继续直至所有必需产物完成、验收通过后再交付。

## 13. Markdown、HTML与公网发布

Markdown报告是唯一内容源；固定HTML模板、CSS、JavaScript和转换器只解析合格Markdown以生成稳定页面，不能手工修改日报HTML来绕过内容或验收。固定关系为：**Markdown → 固定HTML → web/dist**。该设计的受跟踪依据是[静态网页与GitHub Pages设计](superpowers/specs/2026-08-01-news-radar-web-github-pages-design.md)。

待网页隔离分支合入后，预期链路为：Markdown完整性验证 → 固定模板生成`web/dist/` → HTML结构、链接与公开范围检查 → 同步到独立公开仓库`market-news-site` → Git提交/推送 → GitHub Pages。公开仓库只接收`web/dist`；`reports/`、`evidence/`、`.planning/`、`.superpowers/`、内部说明、浏览器快照和本机调试文件都不在白名单。

当前事实与设计目标必须分开：codex/news-radar-web隔离分支已实现且尚未合入main。GitHub认证：暂停；首次推送：暂停；GitHub Pages：暂停；自动任务：暂停。本说明书不恢复认证、不创建或推送公开仓库、不启用Pages，也不修改自动任务。发布失败时保留上一版公开页面及本地成功的Markdown/HTML，不用空目录或半成品覆盖。

## 14. 安全与公开边界

运行只记录完成任务所需的公开页面字段、结构化事件卡和经核验的具体链接。登录状态只能写为“已验证/未验证”与当时可见字段，不能成为读取私人浏览数据的理由。维护者和自动任务**不得读取、写入、输出、持久化或复制**密码、Cookie、Token、Local Storage、浏览器历史、验证码、登录会话、SSH密钥、Git认证配置或环境变量中的凭据；尤其不得读取或输出这些信息。该禁令覆盖本地文件、缓存、构建目录和日志/报告。

内部目录与公开目录必须分离：`evidence/`、`reports/`之外的运行记录、`.planning/`、`.superpowers/`、`HANDOFF.md`、浏览器快照、本机绝对路径（例如`/Users/...`）和本地调试文件不得进入`web/dist/`或公开仓库。生成后先扫描`web/dist/`的文件名、内容和绝对路径/敏感模式；发现任一禁止内容即阻断同步和发布。日志与报告使用来源、状态和失败原因，绝不复制凭据或隐私字段。

## 15. 失败降级与故障排查

降级先保证事实边界和可追溯性，再保证覆盖；任何降级都不能把未取得写成零、把旧值写成当前值，或跳过记录。

| 情形 | 立即处理 | 可交付降级 | 禁止事项 |
|---|---|---|---|
| 来源超时/反爬/网络故障 | 停止无期限等待，记录来源、起止时间和失败类型。 | 使用其他已核来源；条目注明该来源当前未取得。 | 以失败推断“无新闻”或热度为零。 |
| 登录失效或会话不可用 | 记录当前快照未取得；仅检查公开可见路径。 | 沿用旧基线作历史对照，当前结论标“未取得/受限”。 | 读取或输出密码、Cookie、Token、Local Storage或浏览器历史；把旧互动当当前热度。 |
| Chrome进程/控制通道/动态渲染不可用 | 将运行时故障与登录失效分开记录；改走不依赖Chrome的**公开路径降级**。 | 标明**动态字段未取得**；**恢复前置条件**为Chrome进程、可控通道和目标页动态渲染均恢复后重新采集。 | **禁止读取浏览器私密数据**，禁止以历史快照伪装当前动态字段。 |
| 无上一窗口基线 | 保留当前永久URL与字段快照。 | 标“新出现”，仍可参加排序。 | 计算增长率、激增或伪造比较。 |
| 必需字段缺失/时区不明 | 保留原值与缺口；无法解决时降级表述或暂不入榜。 | 写“精确分钟未取得”“来源时区未确认”或缺失字段。 | 补造时间、互动数、公告事实或市场反馈。 |
| Top 10事实或因果冲突 | 交叉复核；不能解决则采用最弱结论。 | 移出深度结论或暂不入榜，保留冲突记录。 | 用强因果或确定性措辞抢时效。 |
| 网页Markdown解析/构建失败 | 非零退出，定位缺失的必需字段；在临时目录完成构建和验收。 | 保留上一份有效`web/dist`和Markdown，记录失败。 | 替换成部分`dist`或手改HTML。 |
| 公开同步、推送或GitHub Pages失败 | 区分报告成功和发布失败；保留本地成功构建。 | 后续在获得授权后重试同一结果。 | 删除/覆盖上一版网站、泄露认证信息或宣称已发布。 |

若15分钟后仍有必要修正、验收或落盘工作，按第11章继续完成并在进度记录说明超时，而非以超时为由停止。
