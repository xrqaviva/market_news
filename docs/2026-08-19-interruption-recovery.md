# 盘前流程中断自愈规则（2026-08-19 固化）

> **背景**：2026-08-19 盘前 cron 07:30 触发，但任务被派到无登录态的会话（sess_eb95ac32），浏览器源全部失败，只抓到 1 个韭研就中断，最终由用户改到有登录态的本会话手动重跑。本次复盘固化"中断自愈"规则，使 cron 无人值守时能自己恢复/降级，不再依赖用户手动接管。

## 核心原则

**任何单独来源失败都不能中断整场盘前运行**。目标是把报告在截点（08:15）前产出来；缺失的是部分源的可选增强，不是报告本身。

## 规则 1：登录态检查失败 → 自动降级，不阻塞

登录态检查（微博/雪球/X/淘股吧）发现无登录态时**不停止**，改用"无需登录"通道完成采集：

| 源 | 无需登录通道 | 缺登录态时的降级 |
|---|---|---|
| 新浪 7×24、东财 7×24 | API（fetch_api_sources.py） | 不受影响（照常全采） |
| 韭研公社 | WebFetch 公开页 / API? 网页 render | 照常（未登录可见帖流） |
| 东财人气榜 | 网页 render | 照常（无需登录） |
| 微博热搜 | 网页 render（热搜榜无需登录可见） | 照常 |
| 淘股吧 | 网页 render | 照常（公开帖+极速快讯可见） |
| 财联社电报 | WebFetch/网页 | 照常 |
| 雪球热股 | 网页 render | 照常（热股榜+热帖无需登录） |
| **X 大V（8 个）** | **WebFetch 公开主页（不依赖 IAB/登录）** | **照常（WebFetch 已是主通道）** |
| X Home timeline | 需登录会话 | 仅此项降级：无登录态则跳过并标注，其余全部可采 |

**结论：即使完全无登录态，也能通过 API + WebFetch + 各站公开网页完成全部核心采集**（仅 X Home timeline 一项缺失，属可选增强）。报告照常产出，在"来源覆盖与核验缺口"注明"登录态缺失，X timeline 未采"即可。

## 规则 2：工具中断/超时/占位符 → 自动重试 N 次

执行中遇到工具异常（返回空、占位符、超时、`guest not attached`、HTTP 5xx、WebFetch 超时等）：

1. **立即重试，先不放弃**：对同一步骤重试 2 次（间隔约 5-10 秒）。
2. **重试仍失败 → 换通道**：浏览器失败改 WebFetch / API；WebFetch 失败改浏览器或改 API。例如 X 大V 页面 WebFetch 超时 → 换某它的可读入口，或用 save_x_scan 落盘已取部分。
3. **换通道仍失败 → 标记缺口并继续**：把该源记入证据文件 + coverage 的 "missing_sources"，**继续执行后续步骤**，不中断整场。
4. **工具输出为占位符/空（如 return 全占位）**：视为工具通道异常，等约 10-20 秒后重试读取结果；确认写入证据文件后再进下一步（避免"以为采到实际没有"）。

## 规则 3：整场流程的保底

- **采集不齐不阻塞生成**：daily_scrum 的 [MISS] 若在反复降级后仍无法补全，**不阻止生成报告**——先按已采部分产出，把缺口写进 coverage。宁可一份"来源较全但有明确缺口标注"的报告，也不能没有报告。
- **测试不过不阻塞发布**：若新报告引入的测试计数变化无法在该次快速修平，也要发布报告本身（dist 可构建即可），测试同步可在次日内补。**报告先行，测试次之**——盘前时效优先于测试计数完美。
- **记录一切**：降级、缺口、重试次数全部写入 evidence/cron-runs.jsonl 的 missing_sources 和 status，确保下次对账可查。

## 与既有规则的衔接

- 本规则是对 docs/OPERATIONS_RUNBOOK.md §8.5 的补充，不替代它；§8.5 仍是要采集的清单，本规则保证清单里某项失败时流程不中断。
- "禁止静默丢弃"仍有效：每一项缺失都必须显式标注（证据 + coverage + cron 日志），不能无声消失。
