# Findings & Decisions

## Requirements
- 报告数量不能过少；前10保留深度，但全面性和准确性优先。
- 标题只写新闻事实，不写“激增、双时点、新出现”等热度方法。
- 每条列标题、核心信息、传播渠道及北京时间；详情紧凑。
- 新闻记录首次可核时间和所有相关时间链；来源链接必须落到具体文章或帖子。
- 老新闻若周末热度明显上升仍可入榜；无旧基线的新节点按新出现比较。
- 财报写盘后或首个可交易时段反馈，说明即时市场认可方向但不推导长期认可。
- 不给操作建议，不以资金验证、个股映射、可靠性或公告确认参与排序。

## Technical Decisions
| Decision | Rationale |
|----------|-----------|
| 内容生成在主项目目录，完成后把新Markdown同步到网页功能分支构建 | 主目录保留全部研究证据与登录采集上下文，功能分支保留稳定构建代码 |
| 发布器默认先dry-run，再显式apply/commit/push | 防止误同步私有证据或错误目录 |
| 公开仓库只接收`web/dist`允许列表 | 证据、计划、本机路径和登录信息不得公开 |
| 额度收紧后先交付提前版Markdown，暂停所有GitHub与HTML动作 | 内容文件是耗时与业务价值核心，固定模板构建可在后续恢复时快速完成 |

## Issues Encountered
| Issue | Resolution |
|-------|------------|
| 主分支尚未合并网页代码，且大量历史报告/证据未跟踪 | 本轮不覆盖或批量暂存主工作树；在隔离功能分支构建和发布 |
| `ps`在当前沙箱中被系统拒绝，无法检查遗留`gh auth login`进程 | 不重复探测系统进程；使用会话轮询或新的非TTY认证方式 |
| AmazingData缺少四项认证环境变量 | 不索取、不输出凭据；交易日和行情改用公开/既有独立来源并披露限制 |
| 上交所官方休市安排搜索无返回 | 不重复相同搜索；按周一常规交易日预期处理，并标明临时停市公告例外 |
| 首个GitHub设备码被页面判定无效 | 生成新码并用逐键输入重试；已进入账户安全验证页 |
