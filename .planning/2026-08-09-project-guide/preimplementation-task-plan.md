# 项目说明书任务计划

## 目标

为 A 股短线新闻雷达生成一份独立、可长期维护的项目说明书，使新使用者无需通读历史报告即可理解项目目标、来源、时间窗口、采集方法、热度与排序规则、报告结构、校验方式、运行边界和后续使用方法。

说明书还必须持久化全部工作步骤、设计与计划索引、完成情况、UAT与集成测试用例、实际结果及证据路径。

## 阶段

- [x] 读取交接、现有规划、发现记录、近期产物与提交历史
- [x] 核对最新设计规范、报告契约、网页发布实现与来源状态
- [x] 确认目标读者为使用者与维护者
- [x] 向用户提出文档结构方案并取得确认
- [x] 写入并提交说明书设计规格，获得用户书面确认
- [x] 创建详细实施计划
- [ ] 生成独立项目说明书
- [ ] 对照真实实现进行术语、权重、路径和状态自审
- [ ] 验证文档链接、占位符、内部一致性和可读性

## 边界

- 只写项目说明文档，不恢复 GitHub 发布任务，不修改自动任务。
- 区分“已实现”“已验证可用”“计划中/受限”，不把历史设想写成当前能力。
- UAT和集成测试不仅列测试思想，还须包含编号、前置条件、步骤、预期结果、当前状态和证据文件。
- 保留安全边界：不读取或输出密码、Cookie、Local Storage、浏览器历史。

## 错误记录

| 错误 | 处理 |
|---|---|
| `HANDOFF.md`包含早期状态，部分权重和登录状态已被后续版本替代 | 以最新设计、报告、测试和实际文件为准，并在说明书中区分历史与当前口径 |
| 沙箱禁止创建`.git/index.lock`，设计规格首次暂存失败 | 不重复普通权限命令；按精确文件路径申请Git写入权限后提交 |
| 精确暂存后`git diff --cached --check`发现文件末尾多余空行 | 删除多余空行，重新暂存并复验后再提交 |
| 实施计划首次缓存检查同样发现文件末尾多余空行 | 删除空行并重新执行缓存差异检查，不提交格式警告 |
