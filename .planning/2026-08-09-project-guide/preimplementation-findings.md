# 项目说明书核验发现

## 已确认

- 项目目标是尽早发现 A 股相关的新闻、海外产业消息和社区传播线索，排序衡量传播热度，不衡量真假或投资价值。
- 当前报告遵循“消息本身优先”：可靠性、资金验证、个股映射和公告确认不参与热点排序，缺失不阻止入榜。
- 时间要求已经从简单“首次发现”升级为：全部换算北京时间，记录本轮可核的最早相关时间，并按从早到晚保留传播时间链。
- 普通交易日窗口从前一交易日 00:00 开始；周一或节假日覆盖前一交易日至下一交易日之间的全部自然日；窗口外旧闻若在本窗口显著升温仍可入榜。
- 核验链接必须落到具体文章、公告或帖子；首页和搜索页只用于发现或记录动态榜位，不能代替单条事实核验。
- 登录渠道必须只读取页面可见字段，不读取账号密码、Cookie、Local Storage 或浏览器历史。
- 报告已经演进为 Top 10 深度条目 + 其余紧凑条目，标题只写事实，热度判断放在详情。
- 最新网页方案采用“先 Markdown、后固定模板生成 HTML”；内容研究和 Markdown 是主要耗时，HTML 构建是快速、可重复阶段。
- 用户确认说明书同时面向普通使用者和项目维护者。
- 用户要求所有工作步骤、设计、计划、完成情况、UAT和集成测试用例及其结果持久化，不能只存在会话文字中。

## 需要继续核对

- 最新有效热点权重（早期交接为30/25/25/15/5，后续报告已变更）。
- 各来源当前状态和具体可采字段。
- HTML 构建、校验、发布代码实际位于哪个分支/工作树，是否已合入主分支。
- 自动任务当前启停状态及说明书应如何表述。

## 最新规范与真实实现

- 当前有效热点权重为：跨渠道覆盖25、变化30、绝对热度20、新鲜度15、频次10；变化为最高单项。
- “激增”只允许同一永久URL、同一字段、两个明确北京时间快照；新URL按“新出现”比较，不伪造百分比；跨平台数字不相加。
- 15分钟是正常条件下的端到端服务目标，不是停止线；超时仍须继续完成全部报告、证据、基线和验收。
- 推荐执行架构是主任务 + 三路并行：海外宏观/财报/地缘、国内政策/产业/公告、登录渠道热度；只有热度组控制登录Chrome。
- Top 10深度字段为：关键信号/预期差、带时间市场反馈、判断边界、后续关键变量；这些字段不参与热度排序。
- 财报必须保留盘后、首个可交易时段或发布日余下交易时段反馈，并标“即时市场定价”；短线价格反馈不等于长期认可。
- IPO进入正式发行阶段后，强制抽取初步询价日、申购日、股票/申购代码、发行数量和已公告上市日；未公告必须明确写待后续公告。
- 网页代码已在隔离工作树`.worktrees/news-radar-web`和分支`codex/news-radar-web`实现，尚未合入`main`。该分支包含解析器、固定模板、构建器、安全扫描、发布器、晨报入口和测试；主分支目前只有网页设计/实施计划。
- 网页设计采用双仓库：私有工作仓库保留报告和证据，公开`market-news-site`仅接收`web/dist`。但GitHub认证、首次推送和Pages发布此前暂停，不能写成已经上线。
